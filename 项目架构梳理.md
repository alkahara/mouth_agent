## 一、项目整体架构

### 1.1 三端关系

```
┌─────────────────┐       HTTPS/JWT        ┌──────────────────────┐    API Key    ┌──────────────────┐
│   微信小程序      │ ──────────────────────▶ │  assistant_chat      │ ─────────────▶ │  sanora_agent    │
│   (sanora)       │ ◀────────────────────── │  (身份网关+Agent代理) │ ◀───────────── │  (AI引擎/LangGraph)│
│   端口: 无(客户端)│                          │  端口: 8001           │               │  端口: 8000       │
└─────────────────┘                          └──────────────────────┘               └──────────────────┘
                                                     │
                                            ┌────────▼────────┐
                                            │   MySQL (用户库)  │
                                            │   端口: 3306      │
                                            └─────────────────┘
```

### 1.2 各端职责

| 项目 | 角色 | 技术栈 | 端口 | 核心职责 |
|------|------|--------|------|----------|
| **sanora** | 小程序前端 | 微信小程序原生(WXML/WXSS/JS) | - | 用户交互、聊天界面、登录页、token管理 |
| **assistant_chat** | 身份网关+Agent代理 | FastAPI + Vue3 + MySQL | 8001 | 用户认证(JWT)、微信登录、请求转发到Agent、用户数据持久化 |
| **sanora_agent** | AI引擎后端 | FastAPI + LangGraph + PostgreSQL | 8000 | 口腔术后分诊对话、RAG知识库、决策树、OpenAI兼容接口 |

### 1.3 调用链

```
用户在小程序输入消息
  → 小程序 request.js 自动携带 Authorization: Bearer <JWT>
  → POST https://sanora.linkwe-inc.com/api/chat
  → assistant_chat 的 get_current_user() 验证JWT
  → assistant_chat 用 Agent API Key 转发到 sanora_agent /v1/chat/completions
  → sanora_agent 执行 LangGraph 口腔分诊流程
  → 结果原路返回
```
