口腔种植术后管理产品需求与系统设计

围绕种植患者术后恢复期的宣教、随访、问题识别、风险分级和医护干预，设计患者端、医护端、Server、知识库与智能对话系统的协同方案。当前智能对话核心以 mouth_cavity_v2_graph 为基础扩展。

定位 产品需求 参考产品补充 知识库设计 系统设计 业务流程图 风险与干预 数据与接口 落地路线

一、产品定位与设计假设

产品目标：对种植患者术后阶段进行持续、分层、可追踪的恢复管理，帮助患者理解正常愈合过程，完成用药、饮食、伤口维护、口腔维护和复诊随访，并在出现异常症状时完成问题识别、风险分级和医护干预。

核心判断：这是一个“医疗安全边界强”的术后管理系统，不应把所有判断都交给自由对话模型。AI 负责理解患者表达、补全信息、生成通俗解释；风险路径、紧急情况、医护预警和前端交互协议应由确定性规则兜底。

设计假设：患者已在院内完成种植相关治疗，系统可以从病例/治疗计划系统读取术式、术区、手术时间、医嘱、复诊计划和联系人等基础信息；患者端为微信小程序，医护端可为小程序或 Web 工作台；智能对话沿用现有 mouth_cavity_v2_graph 的 Manager-Operator 架构。

成功指标

指标类型 建议指标 意义
患者管理 术后宣教触达率、随访完成率、复诊提醒确认率、患者自评填写率 衡量主动管理是否覆盖到恢复期关键节点。
风险识别 异常问题识别率、高风险预警响应时长、医护确认率、误报/漏报复盘数 衡量系统能否及时发现并推动干预。
体验与纠纷预防 患者焦虑问题处理满意度、重复咨询下降率、争议会话可追溯率 降低患者不确定感，沉淀可审计证据链。

二、产品需求

2.1 用户角色

角色 核心诉求 系统能力
患者 知道术后什么是正常、遇到异常时怎么做、是否需要联系医生。 健康宣教、阶段提醒、图片/视频辅助判断、AI 问答、风险建议、医护接管提示。
医生/护士 及时发现风险患者，按优先级处理，减少重复解释和遗漏。 预警列表、患者恢复档案、会话摘要、风险等级、接管对话、随访任务。
运营/质控 维护知识内容、查看随访效果、复盘高风险事件。 知识库管理、问答对管理、版本发布、指标看板、风险事件审计。

2.2 患者端小程序

健康宣教 Guidance

按术后阶段展示短文本、图片和视频，覆盖用药、饮食、伤口维护、口腔清洁、复诊提醒、正常愈合现象和常见误区。文案使用患者能理解的话，少用术语。

智能问答

患者可输入“现在还在出血怎么办”等自然语言问题。系统先判断是否进入问题识别路径，按需追问槽位，再给出风险等级对应建议。

图片/视频辅助判断

对出血、肿胀、口底异常等场景提供标准图片、示例视频和上传入口，辅助患者确认“轻微渗血、活动性出血、其他表现”等选项。

2.3 医护端小程序/工作台

  • 风险队列：按高、中、低风险展示患者，支持筛选术式、医生、术后天数、预警类型。
  • 会话接管：中高风险或患者明确要求人工时，医护可接管对话；接管后 AI 停止自动回复或只做辅助摘要。
  • 患者恢复档案：展示手术信息、医嘱、历史随访、AI 槽位、图片视频、风险等级变化和处理记录。
  • 干预闭环：预警必须有“已查看、已联系、建议复诊、建议急诊、误报、关闭”等处理状态。

2.4 主动 Push 与智能对话的关系

结论：主动 push 不是和 AI 聊天重复。Push 解决“患者没有主动提问时也要被管理”的问题；智能对话解决“患者已经出现问题，需要实时判断”的问题。二者应共享病例阶段和知识库，但触发机制不同。
模块 触发方式 适用内容 是否需要医护预警
主动 Push 按术后时间、术式、医生计划和未完成随访自动触发。 用药提醒、饮食提醒、伤口维护、复诊提醒、随访问卷、正常愈合科普。 问卷异常、患者未读多次、患者自评异常时触发。
智能对话 患者主动提问、上传图片视频、点击“我有异常”。 并发症识别、异常情况分诊、知识库问答、即时处理建议。 由风险等级、关键词、患者情绪和人工请求共同触发。

三、参考医疗智能体 App 补充功能

以下能力根据参考产品截图整理，并结合口腔种植术后管理场景完成取舍。补充能力必须服务于术后管理主流程，不改变“系统不替代医生诊断、处方和急诊处置”的边界。

3.1 对话式首页与快捷入口

对话式首页

以智能体对话为主入口，展示问候语、当前术后阶段、恢复概览和待办提醒。患者无需离开会话即可查看任务、宣教、随访、复诊和异常求助。

恢复数据卡片

以卡片或趋势图展示疼痛、肿胀、体温和任务完成率；数据不足时提示患者补充自评或任务，并说明个性化分析的数据来源。

推荐问题与服务卡片

根据术后阶段推荐常见问题、护理知识和下一步操作，支持点击问题直接咨询、卡片展开收起及跳转到对应任务。

多模态快捷输入

会话输入区支持文字、语音、拍照、相册和附件，提供拍摄提示、预览、重拍和静音播报设置。

会话快捷菜单

提供新建对话、扫一扫、产品介绍和分享入口。分享默认排除患者身份、病历、图片和会话内容，仅允许公开产品页或已脱敏科普内容。

3.2 智能体与专家服务

功能模块 功能要求 完成结果
智能体切换、搜索与分类 支持在术后管理、报告解读、用药助手和就医服务等已审核智能体间切换；可按服务、机构、科室和主题搜索，并始终保留返回术后主智能体的入口。 不同任务由明确服务承接，患者知道当前由谁提供回复。
专家/团队服务卡 展示名称、医院、科室、擅长领域、资质标签、服务量和可用服务；资质、机构和统计数据必须可验证。 患者能够理解服务主体并作出选择。
医生 AI 分身 明确标识 AI 服务及其知识来源、适用范围和与人工医生的关系；涉及诊断、处方、病情恶化或高风险症状时转人工或线下就医。 避免患者把 AI 回复误认为医生本人实时诊疗。
就医服务聚合 按城市查看我的医生、我的医院、挂号记录、复诊计划和订单，并提供拨打医院、路线和到院准备。 线上咨询能够衔接线下就医和复诊。

3.3 健康档案、就诊人与家庭管理

  • 健康档案入口：集中查看基础资料、手术记录、报告、随访、自评、处方医嘱、图片资料和复诊结果，并支持按就诊人切换。
  • 就诊人管理：支持添加、编辑和切换本人及家属；每次咨询、上传、预约和订单必须绑定明确就诊人。
  • 家人档案权限：按就诊人和数据类型授权家属查看、代填、代咨询或接收提醒，授权可查看、修改和撤回。
  • 实名认证：仅在挂号、订单或医疗机构明确要求的场景核验实名，日常科普浏览不强制认证。
  • 个性化回答：由患者决定是否允许系统结合档案、术后阶段和历史会话回答；关闭后使用通用回答并说明能力差异。
  • 长辈模式：支持大字号、高对比度、简化首页、语音播报和家属协助入口，高风险提示不得被简化模式隐藏。

3.4 会话、消息、任务与个人中心

会话与待办

  • 历史会话按时间展示，支持搜索、修改标题、多选归档和删除。
  • 删除前二次确认，并说明关联图片、附件和医疗记录的保留策略。
  • 消息中心聚合医护回复、风险通知和系统消息。
  • 任务中心区分待完成、逾期和已完成任务。

个人与服务

  • 展示挂号记录、复诊安排、服务订单和处理状态。
  • 提供客服咨询、产品反馈、医疗内容举报和投诉进度。
  • 集中展示用户协议、隐私政策、医疗服务说明、公告、产品介绍和版本号。

3.5 隐私保护与安全提示

能力 设计要求
首次隐私授权 说明必要信息、使用目的、保存方式和第三方提供范围，提供“同意并继续”“不同意”和隐私政策全文入口；非必要权限不得与基础服务捆绑。
隐私保护中心 集中查看会话保护状态、设备权限、个性化回答、家属授权和账号注销入口，并允许撤回非必要授权。
位置与设备权限 定位仅用于医院推荐、路线或城市服务；相机、麦克风和相册在使用时申请，并提供拒绝后的替代方式。
安全认证展示 仅展示机构实际取得且仍在有效期内的安全、隐私或人工智能管理认证，并提供认证范围或查询说明。

3.6 优先级与范围

优先级 补充范围 验收重点
P0 对话式首页、推荐问题、多模态输入、新建与历史会话、消息与任务中心、就诊人绑定、首次隐私授权和隐私中心。 患者可从统一会话入口完成咨询与术后关键任务，并能查看和管理授权。
P1 智能体切换与搜索、专家服务卡、健康档案、家属细粒度权限、实名认证、个性化回答、长辈模式、挂号和复诊记录。 患者能按人、按场景获得可识别的服务，老年及家庭照护场景可顺利使用。

四、知识库设计

模块一：种植术后管理宣教知识

面向患者“随时查看”和“按阶段推送”，内容应拆成小颗粒，避免长篇医学说明。建议按以下结构维护：

内容域 示例内容 推荐呈现
正常愈合过程 少量渗血、轻度肿胀、疼痛峰值、拆线前注意事项。 短文卡片 + 时间轴 + 常见问答。
不同时期观察 术后 2 小时、24 小时、3 天、5 天、7 天、拆线前后。 按术后天数自动推送，支持“我已完成”。
并发症和特殊情况识别 出血、疼痛加重、发热、口臭、肿胀、义齿压迫、缝线松动。 图文对照 + 视频指导 + 异常入口。
应对措施 压迫止血、纱布替代、避免诱因、联系医生、急诊/120。 步骤卡片 + 风险提示 + 一键联系。

模块二：问题识别路径

问题识别路径不是普通 FAQ，而是“按需收集信息”的推理路径。当前 mouth_cavity_v2_graph 已具备这个骨架：intent_router 判断是否进入流程，manager 用 LLM 抽取槽位，决策树决定下一问，ask_slot/rag/final/emergency 执行不同响应。

建议继续采用“策略模式 + 注册表模式”：每一种术后问题是一条 Flow，如出血、感染、疼痛、肿胀、义齿压迫、药物不良反应等；每条 Flow 定义自己的触发词、槽位、风险评估和护理方案。

Flow 核心槽位 输出
术后出血 是否手术区域、诱因、术后时间、术式、出血表现、能否压迫、压迫后是否复发。 风险等级、护理方案、图片/视频、医护预警。
疑似感染 发热、疼痛变化、口臭/脓液、伤口裂开、全身乏力、术后天数。 复诊建议、用药提醒、医护确认任务。
疼痛/肿胀 疼痛评分、肿胀范围、是否加重、是否影响吞咽/呼吸、用药情况。 正常恢复解释、警示条件、是否升级处理。

模块三：问题风险等级

风险等级是系统联动医护干预的核心字段。建议保持四级：无风险、低风险、中风险、高风险，并将每一级绑定响应时限、患者话术、医护任务和审计要求。

五、系统设计与运转方式

患者端小程序

  • 首页展示当前术后阶段、今日任务、异常提问入口。
  • Guidance 中心按术式和时间展示宣教内容。
  • AI 对话支持文字、选项、图片、视频和结构化卡片。
  • 高风险时展示“立即联系/急诊/拨打 120”等操作入口。

医护端小程序/工作台

  • 预警队列按风险等级和处理时限排序。
  • 进入患者详情后查看病例、会话、槽位和图片。
  • 可接管对话、补充医嘱、创建复诊/电话任务。
  • 所有干预动作进入审计日志。

Server 与中台服务

系统 职责 关键设计
API Gateway / Chat Server 统一接入小程序请求，鉴权、限流、SSE/流式响应、会话管理。 患者端和医护端使用不同权限；高风险响应不能被客户端静默吞掉。
智能体编排服务 调用 mouth_cavity_v2_graph，管理 thread_id、模型、上下文和状态恢复。 保留 Postgres checkpoint，确保多轮槽位不会串线。
病例上下文服务 从 HIS/CRM/病例系统读取术区、术式、时间、医嘱、复诊计划。 只向模型暴露必要字段；关键字段需要结构化注入，不依赖患者自述。
知识库/RAG 服务 维护宣教知识、问答对、护理方案、图片视频、版本发布。 内容分为患者可见、医护可见和模型可检索三类。
随访与 Push 服务 按术后阶段生成任务和提醒，发送微信订阅消息或站内提醒。 基于术式、术后天数和未完成状态触发；异常问卷进入预警。
预警与接管服务 根据风险等级创建医护任务，支持接管、升级、关闭和复盘。 高风险即时通知，中风险限时处理，低风险可进入观察队列。

推荐架构原则

  • 确定性优先：紧急情况、风险分级、医护预警和前端结构化协议用代码规则保证。
  • AI 做理解与表达：模型负责槽位抽取、意图识别、患者友好表达和知识库问答。
  • 医护可接管：一旦进入人工模式，系统应明确标记，避免 AI 与医护同时给出冲突建议。
  • 知识可版本化：每次风险建议都记录命中的 Flow、护理方案版本和知识来源，便于复盘。

七、风险等级与医护干预策略

等级 患者端响应 医护端动作 处理时限建议
无风险 解释正常愈合现象，推送日常维护和观察要点。 不进入预警，仅记录到恢复档案。 无需实时处理。
低风险 给出护理建议、避免诱因、提醒继续观察。 进入观察队列，可在日常随访中查看。 下一次随访前查看。
中风险 建议联系医生或尽快复诊，解释为什么需要进一步确认。 创建预警任务，推送给责任医生/护士，可接管对话。 建议 2 小时内确认，门诊时间外按机构规则处理。
高风险 明确提示急诊/120/立即就医，避免继续等待 AI 回复。 即时强通知医护，自动升级为高优先级事件，必须闭环。 即时处理，未响应需升级通知。
医护介入规则建议：高风险必须介入；中风险默认创建任务并建议人工确认；低风险在患者连续追问、上传异常图片、情绪焦虑或重复触发同类问题时升级到人工关注。

八、数据与接口设计

8.1 对话输入上下文

字段 来源 用途
patient_id / thread_id 小程序登录态 隔离会话、恢复槽位、关联患者档案。
surgery_type / surgery_area 病例系统 辅助风险判断，减少患者重复填写。
postop_day / surgery_time 病例系统 匹配恢复阶段和宣教内容。
messages / media 患者端 进入意图识别、槽位抽取和图片/视频辅助判断。

8.2 对话输出协议

建议继续使用文本 + additional_kwargs 的方式，让前端渲染结构化组件。

输出字段 前端用途
options / multi_select 渲染患者可点击选项，减少自由输入造成的误解。
image_url / video_url 辅助患者确认出血、肿胀等情况，或学习压迫止血步骤。
slot_update 医护端展示槽位收集进度；患者端可选择不展示。
triage_result 渲染风险等级卡片，并触发医护预警服务。
handoff_required 提示患者等待医护确认，并切换到人工接管状态。

8.3 知识库运营

  • 问答对按场景维护：出血、疼痛、感染、用药、饮食、口腔清洁、复诊、义齿/保持器、特殊人群。
  • 每条知识应有适用人群、术后阶段、风险等级、患者可见版本、医护可见版本和审核状态。
  • 护理方案应版本化，AI 输出时记录 care_plan_id 和版本，便于追责与迭代。
  • 高风险相关知识不允许只靠 RAG 自由生成，应由固定模板和规则优先输出。

九、落地路线

阶段 范围 验收标准
P0：出血流程闭环 基于现有 mouth_cavity_v2_graph，完成患者端问答、选项、图片/视频、风险卡片和医护预警。 出血常见路径可稳定完成槽位收集；高风险可强制预警；医护能查看完整上下文。
P1：主动随访与宣教 按术后时间和术式配置 push 任务，完成宣教内容库和随访问卷。 患者能收到阶段提醒；异常问卷可进入预警队列。
P2：扩展并发症 Flow 新增感染、疼痛/肿胀、药物不良反应、义齿压迫等问题识别路径。 每条 Flow 有槽位、风险等级、护理方案和回归测试用例。
P3：质控与运营 知识版本管理、预警复盘、医生响应看板、患者体验指标。 能追踪每次 AI 建议来源，支持误报/漏报复盘和知识迭代。
